At Uber, AI isn’t just a side project—it’s the new standard for how work gets done. With over 5,000 engineers and thousands of non-technical users relying on agentic workflows, the company now executes 60,000 AI agent tasks per week. The secret? A protocol called MCPs (Multi-Tool Calling Protocols) that transforms chaos into order at enterprise scale.

This isn’t about incremental improvements. It’s about solving a fundamental problem: how do you make AI usable when your organization runs on 10,000+ services, 1,500+ active agents, and a knowledge base scattered across a complex microservices landscape? Without MCPs, every agent would need to rediscover how to interact with each service—an impossible task that would collapse under its own complexity. Instead, Uber’s system automates tool discovery, enforces standardization, and scales AI adoption across the entire company.

Why Ad-Hoc AI Tooling Was Holding Uber Back

Before MCPs, Uber’s AI agents operated in silos. Each agent had to learn how to interact with individual services—an approach that worked for small-scale experiments but failed at enterprise scale. With 10,000+ services and 1,500 monthly active agents, the lack of standardization created three critical bottlenecks:

  • Tool Discovery Overload: Agents wasted cycles relearning how to call the same services, leading to redundant work and inefficiency.
  • Security Risks: Without a unified way to validate tool usage, malicious or poorly designed agents could introduce vulnerabilities.
  • Context Bloat: Agents struggled with memory limits as they loaded unnecessary tool definitions, degrading performance.

The breakthrough came when Uber realized that AI agents didn’t need to understand every service—they needed a standardized way to interact with them. MCPs act as a translation layer, converting service interfaces into agent-friendly tools. This shift didn’t just improve efficiency—it made AI adoption possible at Uber’s scale.

Inside MCPs: Architecture & Design Choices

Uber’s MCP system is built around three core components:

  • Gateway Orchestrator: Automatically crawls Uber’s 10,000+ services—parsing proto and thrift files—to generate MCP tool descriptions. This eliminates manual tool registration and ensures agents always have access to the latest service definitions.
  • LLM-Powered Tool Generation: Uses large language models to convert service metadata (message names, comments) into natural language tool descriptions. This bridges the gap between human-readable instructions and machine-executable code.
  • Conflict Provider & Registry: Serves MCP definitions to consumers—whether no-code agent builders, SDKs, or coding agents—while enforcing security scans and version control. Every update triggers a diff, which is validated by Uber’s engineering security APIs before deployment.

The system’s real power lies in its automation. Service owners can update their MCP definitions, and the changes propagate seamlessly—no manual intervention required. This creates a self-sustaining loop: as services evolve, agents automatically gain access to new capabilities without breaking existing workflows.

Uber’s architecture also addresses a lesser-known but critical challenge: context bloat. By loading tool definitions on demand rather than upfront, agents avoid hitting memory limits—a problem that plagues many enterprise AI systems. The result? Faster execution, lower costs, and more reliable performance.

MCPs in Action: Results at Uber’s Scale

The numbers tell the story:

  • 60,000+ weekly executions: MCPs handle this volume without degradation, proving the system’s scalability.
  • 1,500+ monthly active agents: From internal productivity tools to team workflow automation, agents are now ubiquitous at Uber.
  • 90%+ of engineers: Use AI for agentic workflows every month—a figure that continues to grow as non-engineering teams adopt the technology.
  • Zero manual tool registration: The Gateway Orchestrator eliminates this bottleneck, allowing Uber to scale AI adoption without proportional increases in overhead.

But the real impact goes beyond metrics. MCPs have transformed how Uber operates—turning AI from a niche experiment into a core part of the company’s infrastructure. Teams no longer need to build custom integrations for every agent. Instead, they rely on a standardized protocol that works across all services, reducing friction and accelerating innovation.

What This Means in Practice

At Uber, MCPs power three key surfaces:

  • Uber Agent Builder: A no-code platform that lets non-technical users create agents for productivity and workflow automation. Thousands of these agents are active monthly, automating tasks that once required manual effort.
  • SDKs & Coding Agents: Developers use MCPs to build custom agents that integrate seamlessly with Uber’s services. The protocol ensures consistency, so agents behave predictably regardless of who built them.
  • Internal Agent Platform: A centralized hub where teams can discover, share, and reuse agent skills—think of it as a marketplace for AI workflows. This fosters collaboration and reduces redundant work.

One surprising insight? MCPs aren’t just about efficiency—they’re about democratizing AI. By abstracting away the complexity of service interactions, Uber has made AI accessible to non-engineers. Teams across the company—from operations to customer support—now build and deploy agents without writing a single line of code.

This shift has also changed how Uber thinks about AI governance. With MCPs, every tool interaction is logged, scanned for security issues, and version-controlled. This creates an audit trail that’s critical for compliance and debugging—something ad-hoc AI tooling simply can’t provide.

Limitations & Open Questions

Despite its success, Uber’s MCP system isn’t without challenges. The biggest? Tool discovery accuracy. While the Gateway Orchestrator automates tool generation, not all descriptions are equally useful. Some services lack clear documentation, leading to ambiguous or incomplete tool definitions. Uber is addressing this with a new tool search feature that improves discovery and reduces context bloat—but it’s an ongoing effort.

Another limitation is skill sharing. While MCPs standardize tool usage, teams still need ways to share best practices for agent workflows. Uber is experimenting with "skills"—reusable recipes for MCP interactions—that can be evaluated, A/B tested, and shared across the company. This is still in development, but it could unlock the next level of AI collaboration.

The Road Ahead

Uber’s MCP system is a glimpse into the future of enterprise AI. The next phase? Expanding beyond internal use. The company is exploring ways to make MCPs shareable across organizations—imagine a world where AI agents can seamlessly interact with services from different companies, all using the same standardized protocol.

Another focus is evaluations. Uber is building tools to assess the quality of agent outputs, the correctness of skill invocations, and the performance of different skill versions. This will enable A/B testing for AI workflows—something that’s currently rare in enterprise settings.

For now, one thing is clear: MCPs have solved a problem that was holding AI back at scale. By standardizing tool interactions, Uber hasn’t just made AI usable—it’s made it indispensable.
